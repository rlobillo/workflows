# CNV Bug Triage Workflow

LLM-assisted Jira bug triage agent for CNV (OpenShift Virtualization) bugs. Analyzes issues,
identifies missing triage fields, and suggests values — without ever modifying bug fields directly.

## Core Principle

**This workflow is read-and-suggest only. It never modifies Jira fields. It only analyzes, suggests, and optionally posts structured comments for human review.**

## What Makes a Bug Fully Triaged?

A bug is considered FULLY TRIAGED when ALL five of these fields are populated:

| Field | Description |
|-------|-------------|
| Assignee | Developer responsible for the fix |
| QA Contact | QE engineer responsible for validation |
| Sprint | Active or future sprint (not backlog) |
| Priority | Non-Undefined (Critical, Major, Minor, Normal) |
| Fix Version | Target release version |

## Available Commands

| Command | Description |
|---------|-------------|
| `/triage` | Fetch and analyze all untriaged CNV bugs; generate triage report |
| `/triage-bug [KEY]` | Deep-dive analysis of a single bug (fields + backport + duplicates) |
| `/post-comments` | Post structured triage suggestions as Jira comments |
| `/duplicate-check` | Identify potential duplicate bugs among open issues |
| `/backport-analysis` | Analyze resolved bugs for backport needs across releases |
| `/report` | Generate comprehensive triage status dashboard |

## Typical Workflow

```text
# 1. Start with a full sweep
/triage

# 2. Deep-dive on a specific bug
/triage-bug CNV-12345

# 3. Check for duplicates
/duplicate-check

# 4. Analyze backport needs
/backport-analysis

# 5. Post suggestions to Jira (requires confirmation)
/post-comments

# 6. Generate a status report
/report
```

## Output Artifacts

All outputs are saved in `artifacts/cnv-bug-triage/`:

```text
artifacts/cnv-bug-triage/
├── triage-report.md      # Full list of untriaged bugs with suggestions
├── bug-{KEY}.md          # Individual bug deep-dive analysis
├── duplicates-report.md  # Potential duplicate pairs with confidence scores
├── backport-report.md    # Resolved bugs needing backport evaluation
└── full-report.md        # Comprehensive triage status dashboard
```

## Jira Comment Format

When `/post-comments` is run, each comment follows this structure:

```
[Bug Triage Agent] Triage Analysis

Missing fields: <comma-separated list>

Suggestions:
- Priority: <value> — <reasoning>
- Assignee: <name> — <reasoning>
- QA Contact: <name> — <reasoning>
- Sprint: <sprint name> — <reasoning>
- Fix Version: <version> — <reasoning>

Backport: <yes / no / investigate> — <reasoning>

Potential duplicates: <list with confidence %> or None identified

---
This comment was generated by the CNV Bug Triage Agent. These are suggestions only —
no fields have been modified. Please review and apply as appropriate.
```

A 7-day cooldown per bug prevents repeat comments.

## Jira MCP Integration

This workflow uses the Atlassian/Jira MCP server tools:

- `searchJiraIssuesUsingJql` — fetch bugs by JQL query
- `getJiraIssue` — get full details for a specific issue
- `addCommentToJiraIssue` — post triage comments
- `lookupJiraAccountId` — resolve team member identities

## Default JQL Filters

Untriaged bugs:

```
project = CNV AND issuetype = Bug AND status not in (Closed, Resolved, "Won't Fix")
AND (priority = Undefined OR assignee is EMPTY OR fixVersion is EMPTY)
```

Recently resolved (for backport analysis):

```
project = CNV AND issuetype = Bug AND status in (Resolved, Closed)
AND resolutiondate >= -30d AND resolution = Fixed
```

## Configuration

This workflow is configured in `.ambient/ambient.json`. Key sections:

- `systemPrompt`: Agent behavior, suggestion guidelines, comment format
- `startupPrompt`: How the agent introduces itself to users
- `results`: Artifact path documentation
