# /post-comments - Post Triage Suggestions as Jira Comments

## Purpose

Reviews triage analysis artifacts and posts structured [Bug Triage Agent] comments to untriaged
Jira bugs. Respects a 7-day cooldown per bug to avoid spam. NEVER modifies bug fields directly.

## Prerequisites

- At least one of `/triage` or `/triage-bug` must have been run first to generate analysis artifacts
- Jira MCP server must be configured with write access (comment posting)
- User must confirm they want to post comments before proceeding

## Process

1. **Load triage artifacts**
   - Read `artifacts/cnv-bug-triage/triage-report.md` if it exists
   - Read any `artifacts/cnv-bug-triage/bug-*.md` files for individual analyses
   - Build a list of bugs with pending suggestions

2. **Confirm with user**
   - Show the user how many bugs have suggestions ready to post
   - Ask for explicit confirmation before posting any comments
   - Allow user to exclude specific bugs if desired

3. **Check cooldown per bug**
   - For each bug in the list, fetch its existing comments from Jira
   - Search for comments containing `[Bug Triage Agent]`
   - If a matching comment was posted within the last 7 days: skip the bug, log it as "cooldown active"
   - If no recent comment: proceed to post

4. **Format and post comment**
   - For each eligible bug, post a comment with this structure:
     ```
     [Bug Triage Agent] Triage Analysis

     Missing fields: <comma-separated list of missing fields>

     Suggestions:
     - Priority: <value> — <reasoning>
     - Assignee: <name> — <reasoning>
     - QA Contact: <name> — <reasoning>
     - Sprint: <sprint name> — <reasoning>
     - Fix Version: <version> — <reasoning>

     Backport: <yes / no / investigate> — <reasoning>

     Potential duplicates: <list with confidence %> or None identified

     ---
     This comment was generated by the CNV Bug Triage Agent. These are suggestions only — no fields have been modified. Please review and apply as appropriate.
     ```
   - Only include sections for fields that are actually missing or relevant
   - Use `addCommentToJiraIssue` MCP tool to post

5. **Report results**
   - Show a summary: posted / skipped (cooldown) / failed
   - List any bugs where posting failed with the error reason

## Output

- **Posted comments**: directly in Jira (no local artifact)
- **Comment log**: reported inline in the conversation (not saved to disk unless requested)

## Usage Examples

Post comments for all analyzed bugs:

```
/post-comments
```

## Success Criteria

After running this command:

- [ ] User explicitly confirmed before any comment was posted
- [ ] Cooldown check performed for each bug (7-day window)
- [ ] Comments posted only to bugs without recent [Bug Triage Agent] comments
- [ ] Summary of posted / skipped / failed shown to user

## Next Steps

After posting comments:

1. Review comments in Jira and apply suggestions as appropriate
2. Re-run `/triage` after applying changes to track progress
3. Run `/report` to see updated triage status

## Notes

- **NEVER modify Jira fields** — this command only adds comments
- Always get user confirmation before posting; never post autonomously
- If no triage artifacts exist, prompt the user to run `/triage` first
- Failed posts should be logged clearly; do not silently drop them
- The cooldown is per-bug, not per-session — check actual comment timestamps in Jira
